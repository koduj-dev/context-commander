Mockups

Sixteen screens of the Context Commander management plane, built from one kit on the real brand tokens. Static HTML — open any file, no build step.

Foundations
These are mockups, not the product. Every control that the backend cannot actually perform is either absent or disabled with a reason — member removal, secret rotation, SSO, integrations. A mockup that promises capability is a bill the implementation has to pay.

How this is built

Colour
Imported straight from docs/brand/tokens/ui-colors.css. No hex is written in the mockup stylesheet — change a token and every screen follows.
Logo
Referenced from docs/brand/svg/. Not redrawn, not recoloured.
Components
One stylesheet, one shell, one component library. A page is composed, not authored — so no screen is its own experiment.
Themes
Dark is the default and the stronger brand expression; the toggle at the top of every page switches to light.

What the screens deliberately avoid

Not a database browser. Artifacts, events, conversations and history objects appear where they answer a management question — not as one tab per table.
No decorative brand. Pink marks the context you are in, violet the context you inherit. Neither fills a surface.
No invented events. The activity screens show only action names the server actually emits.
