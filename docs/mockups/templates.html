Templates

A template is a snapshot of a project that was shaped the way you want new ones to start: its skill bindings, its policies and its context notes. Not a fork — no handoffs, no history, no secrets travel with it.

Proposed, not built. Every other screen here shows only what the server can already do. This one shows a flow that is decided but not implemented, so nothing in it is wired.

What a template carries

Copied
Skill bindings · gate bindings · artifacts under context/
Never copied
Handoffs · conversations and history · secrets · events · audit
Those belong to the work that happened, not to the shape of a project. A template that dragged a handoff into a new project would be handing someone else's unfinished task to a stranger.

Two operations, no third

Save this project as a template
A button on the project, once it is shaped the way you want.
On Settings
Create a project from a template
Applies the bindings on your behalf, with your authorization.
No template editor. You shape a real project until it is right, then save what it became — an authoring surface for templates would be a second thing to keep correct.

Provenance

A project created from a template records which template and which version it came from, and so does every artifact copied in.

project.created from_template: "Elasticsearch migration" v3\ncontext/overview.md copied_from_template: v3
An artifact that arrives with no record of where it came from is how two projects quietly diverge from the same text with nobody owning either.
